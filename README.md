# ARMOR —— 面向易语言/32 位程序的压缩保护壳

> 一条命令压缩到约 60%，图标版本版权原样保留，还能给 DLL 加壳
> 对比 UPX 等海外压缩壳、VMProtect（VMP）保护壳：到底怎么选？

---

## 一、ARMOR 是什么

ARMOR 是一款针对 **32 位 x86 Windows PE 程序（尤其易语言静态编译程序）** 的 **压缩 + 保护** 壳。用法极简：一条命令，把原始 EXE（或 DLL）变成加壳后的文件。

加壳后能做到：

- **体积显著变小**：实测易语言程序 684032 字节 → 425984 字节（**约 62%**），全功能保留；
- **图标、版本版权完整保留**：磁盘图标、文件属性里的版本/版权信息、**运行时窗口标题栏图标**都与原程序一致；
- **内置多层保护**：载荷 RC4 加密、反调试、反转储（anti-dump）、易语言特征隐藏、载荷 CRC 校验；
- **支持 32 位 DLL 加壳**：导出函数、导入表、重定位表原样保留，`LoadLibrary` / `GetProcAddress` / 调用 / `FreeLibrary` 全部正常；
- **一键解压还原**：随时把加壳产物还原成与原件**逐字节一致**的原始文件，方便备份与恢复。

一句话：**压缩瘦身为主、防破解门槛为辅，专为易语言生态设计。**

---

## 二、为什么你需要它（常见痛点）

给程序加壳的人，多少都踩过这些坑：

| 痛点 | 说明 |
|---|---|
| 加壳后图标没了 / 版本信息丢了 | 很多壳默认压缩资源节，图标、版权、版本全丢 |
| 杀软误报高 | 壳特征太明显，被当成木马 |
| 加壳后程序跑不起来 | 兼容性差，或资源被破坏 |
| 不能给 DLL 加壳 | 导出、导入表一压就废 |
| 用了 UPX 等于没加壳 | 一条 `upx -d` 就还原了 |
| VMP 太贵太重量级 | 虚拟化膨胀、卡顿、误报，还收费 |

ARMOR 针对这些场景逐一做了取舍：默认保留资源节、节名可自定义降特征、DLL 原生支持、加密 + 反调试 + 反转储、免费使用。

## 三、核心特性一览

1. ✅ **压缩率高**：自研 DEFLATE 压缩（zlib 兼容），实测压缩至约 60%；
2. ✅ **保留图标与版本版权**：资源节默认不压缩，磁盘与运行时窗口图标一致；
3. ✅ **载荷 RC4 加密**：压缩载荷加密，无法直接还原明文代码；
4. ✅ **反调试**：检测到调试器可退出 / 行为异常 / 增强检测（窗口、进程名、计时）；
5. ✅ **反转储（anti-dump）**：运行后混淆内存中的 PE 头，提高 dump 还原难度；
6. ✅ **易语言特征隐藏**：内置易语言特征库，自动扫描并加密隐藏特征字节，降低被工具/杀软特征识别命中的概率；
7. ✅ **载荷 CRC 校验**：防止加壳产物被篡改；
8. ✅ **DLL 加壳**：`--allow-dll`，导出/导入/重定位表保留，加载调用正常；
9. ✅ **自定义产物节名**：`.arm0/.armr/.arm1` → `.shield0/.shieldr/.shield1`，避开固定特征；
10. ✅ **配置文件**：所有参数可写进 INI，配合 `--config=` 复用，命令行可覆盖；
11. ✅ **一键解压还原**：`--unpack` / `unpack` 子命令 / 配置 `unpack=1`，还原后与原文件逐字节一致；
12. ✅ **零依赖交付**：日常使用**只需一个 `ArmorCLI.exe`**，无需安装、无需运行其他工具。

## 四、快速上手（一条命令）

```bat
:: 给易语言程序加壳（默认全开，保留图标与版本信息）
ArmorCLI.exe pack 你的程序.exe 你的程序_packed.exe

:: 给 DLL 加壳
ArmorCLI.exe pack my.dll my_packed.dll --allow-dll

:: 一键解压还原
ArmorCLI.exe unpack 你的程序_packed.exe 还原.exe
```

默认配置已包含：载荷加密、反调试（exit）、反转储、CRC 校验、易语言特征隐藏、保留图标与版本信息。加壳后直接运行，功能与原版完全一致。

## 五、调用参数（完整）

### 常用参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `pack <输入> <输出>` | 加壳命令 | — |
| `unpack <加壳文件> <还原文件>` | 一键解压还原（等价 `--unpack`） | — |
| `scan <输入>` | 只扫描分析，不写文件 | — |
| `--level=N` | 压缩级别 1..9 | 6 |
| `--encrypt=0\|1` | 载荷 RC4 加密 | 1 |
| `--anti-debug=none\|exit\|fake` | 反调试动作 | exit |
| `--anti-debug-level=1\|2` | 反调试强度（2 增强：窗口/进程名/计时） | 1 |
| `--anti-dump=0\|1` | 反转储（防 dump） | 1 |
| `--hide-features=模式` | 易语言特征隐藏：`auto\|none\|all\|名称;名称` | auto |
| `--keep-manifest=0\|1` | 保留清单资源（权限/视觉样式） | 1 |
| `--keep-rsrc=0\|1` | **资源节不压缩（保留图标/版本版权）** | 1 |
| `--crc=0\|1` | 解包前校验载荷 CRC | 1 |
| `--force` | 忽略"重复加壳"等告警 | 关 |
| `--allow-dll` | 允许对 32 位 DLL 加壳 | 关 |
| `--section-prefix=<前缀>` | 自定义产物节名前缀（1..6 个字母数字） | arm |
| `--unpack` | 一键解压还原（等价独立子命令 `unpack`） | 关 |
| `--config=<路径>` | 从配置文件加载参数（命令行优先） | 无 |

### 常用组合示例

```bat
:: 最高压缩比
ArmorCLI.exe pack app.exe app_packed.exe --level=9

:: 增强反调试 + 自定义节名降特征
ArmorCLI.exe pack app.exe app_packed.exe --anti-debug-level=2 --section-prefix=shield

:: 关闭反调试（调试自己程序时）
ArmorCLI.exe pack app.exe app_packed.exe --anti-debug=none

:: DLL 加壳 + 自定义节名
ArmorCLI.exe pack my.dll my_packed.dll --allow-dll --section-prefix=shield

:: 全部参数写进配置文件复用
ArmorCLI.exe pack app.exe app_packed.exe --config=armor.ini
```

配置文件（`armor.ini`）示例：

```ini
level=9
anti-debug=exit
anti-debug-level=2
anti-dump=1
keep-rsrc=1        ; 保留图标/版本版权
crc=1
section-prefix=shield
unpack=0           ; 设为 1 时该次调用做一键解压还原
```

退出码：`0` 成功、`1` 参数错误、`2` 输入输出错误、`3` 不支持的目标、`4` 处理失败。

## 六、与 UPX 等海外压缩壳的区别

**UPX** 是全球最流行的开源压缩壳，ARMOR 与它的核心差异在"**压缩之外还做不做保护**"：

| 维度 | ARMOR | UPX |
|---|---|---|
| 定位 | 压缩 + 加密 + 反调试 + 反转储综合壳 | 纯压缩壳 |
| 体积 | 约 60%（保留资源 + 加密） | 压缩率通常更高 |
| 保护强度 | 中：载荷加密、反调试、反转储、特征隐藏 | 弱：无任何保护 |
| 脱壳难度 | 需逆向外壳 + RC4 密钥 + 反调试/反转储干扰 | 极低：官方 `upx -d` 一条命令还原 |
| 图标/版本保留 | ✅ 完整保留（磁盘 + 运行时窗口图标） | 一般，压资源节可能出现异常 |
| 杀软误报 | 节名可自定义 + 特征隐藏，可降低特征命中 | UPX 特征全球黑名单，识别率极高 |
| 易语言适配 | ✅ 内置特征库与特征隐藏 | 通用壳，无感知 |
| 费用 | 免费 | 开源免费 |

**结论**：UPX 适合"只要压小、不要保护"的场景；一旦你的程序需要防止被一键脱壳、被特征识别，UPX 等于裸奔。ARMOR 在压缩的同时把保护门槛一起拉起来。

---

## 七、与 VMProtect（VMP）保护壳的区别

**VMProtect** 是商业代码虚拟化保护壳，ARMOR 与它的核心差异在"**保护思路与代价**"：

| 维度 | ARMOR | VMProtect（VMP） |
|---|---|---|
| 保护思路 | 压缩 + 载荷加密 + 反调试 + 反转储（原生执行） | 把关键代码翻译成私有虚拟机字节码（代码虚拟化） |
| 体积 | 变小（约 60%） | 增大（虚拟化代码膨胀） |
| 运行开销 | 几乎无损，原生执行 | 虚拟化解释执行，性能下降明显 |
| 保护强度 | 中高：适合防一键脱壳、防静态分析 | 极高：适合核心算法/关键逻辑防逆向 |
| 兼容性 | 开关可控、节名可自定义、特征可隐藏，易适配 | 反调试/反虚拟机检测激进，误报与兼容问题更常见 |
| 误报 | 可调参降低 | 普遍偏高 |
| 费用 | 免费 | 商业付费授权 |
| 与易语言 | ✅ 针对易语言优化 | 需自行处理易语言特征 |

**结论**：VMP 强在"把核心代码变成虚拟机"，但代价是体积膨胀、性能下降、误报高、要付费；ARMOR 强在"整体瘦身 + 基础防破解门槛 + 零成本 + 易语言友好"。两者**不冲突**——常见做法是先拿 ARMOR 整体压缩瘦身，再对最核心的算法/逻辑用 VMP 虚拟化，一个管体积、一个管核心。

## 八、怎么选：一张表看懂

| 需求 | 推荐 | 理由 |
|---|---|---|
| 只想把程序压小 | UPX / ARMOR | 追求极致压缩选 UPX；想顺便加点保护选 ARMOR |
| 防一键脱壳、防特征识别、保留图标版本 | **ARMOR** | 加密 + 反调试 + 反转储 + 节名自定义 + 资源保留 |
| 给易语言程序加壳 | **ARMOR** | 特征隐藏 + 兼容性好，不用再折腾易语言特征 |
| 给 DLL 加壳 | **ARMOR** | `--allow-dll` 原生支持，导出导入重定位保留 |
| 核心算法/关键逻辑高强度防逆向 | VMProtect | 代码虚拟化，可配合 ARMOR 压缩瘦身 |
| 免费 + 轻量 + 不想装环境 | **ARMOR** | 单文件 ArmorCLI.exe，命令行一条搞定 |

## 九、注意事项（建议仔细看）

1. **加壳前先备份原文件**：虽然内置 `--unpack` 可一键还原（还原结果与原文件逐字节一致），但养成先备份的习惯更稳妥；
2. **杀软误报**：任何加壳都可能触发误报。可通过**自定义节名前缀**（`--section-prefix=shield`）、关闭特征隐藏（`--hide-features=none`）、调整参数来降低误报，必要时向杀软厂商申诉；
3. **仅支持 32 位（x86）PE**：64 位程序、.NET 程序暂不支持；
4. **调试自己程序时**：默认反调试是"检测到调试器就退出"，联调请加 `--anti-debug=none`；
5. **任何壳都不是绝对安全**：加密保护是提高破解门槛，不是"永久防破解"。建议配合正版授权校验、服务端验证等手段；
6. **DLL 加壳注意**：DLL 加壳需 `--allow-dll`，`--anti-dump` 在 DLL 模式下自动跳过，属正常设计。

## 十、获取与使用

- 自研免费工具，**只有一个 `ArmorCLI.exe`**，无需安装、无需运行其它组件；
- 命令行风格，Windows 下直接运行，支持中文路径；
- 支持把参数写进配置文件批量复用，适合打包进你自己的发布流程；

> 本项目仍在持续迭代（压缩算法、DLL 支持、解压还原、自定义节名等均为已验证功能），欢迎交流反馈。
